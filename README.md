# Why Four Keyholders Learn Nothing

**Shamir secret sharing and the internet's DNSSEC root key.** This is a one-page interactive website for the MATH 301 Discrete Mathematics project of Team 2, Baku Higher Oil School (lecturer Samra Aghayeva, Fall 2026/27).

Team: Nurtaj Heydarli, Farida Aliyeva, Nazrin Miriyeva, Rabiya Alizada, Mahammad Gulmammadov.

> Any 5 of 7 rebuild the key. Any 4 learn nothing.

## What's inside

| Path | Purpose |
|---|---|
| `index.html` | The single page: hero, problem, idea, counting, worked example, the 17 polynomials, proof, assumptions, lab, verification |
| `css/style.css` | All styles (dark theme, responsive, respects `prefers-reduced-motion`) |
| `js/shamir.js` | The math module: exact BigInt modular arithmetic (shares, Lagrange weights, extended Euclid, Miller–Rabin, Lucas–Lehmer, counting, broken-assumption experiments) |
| `js/main.js` | Page visuals and animations (GSAP + ScrollTrigger, Lenis smooth scroll, KaTeX) |
| `js/extras.js` | Video-inspired layer: drifting ghost words, glitch headings, the ring of seven holders, the “two fingers meet” scroll scene (our own line drawing after Michelangelo's *Creation of Adam*) and the Thank You finale |
| `js/lab.js` | The interactive lab: Split, Rebuild, Group counter, Inverse finder, Break an assumption, Real size (p = 2^521 − 1) |
| `tests/shamir.test.mjs` | Unit tests for the math module |
| `vendor/` | Local copies of GSAP 3.15 (core, ScrollTrigger, ScrambleText), Lenis and KaTeX 0.16, so the site works offline |

It is plain HTML, CSS and JavaScript (ES modules). There is no framework, no build step and no backend.

## Run locally

ES modules need a web server (opening the file directly with `file://` will not load them):

```bash
python3 -m http.server 8000
```

Then open <http://localhost:8000>. Any static server works, for example `npx serve`.

## Run the tests

Needs Node.js 18 or newer. There are no dependencies to install.

```bash
npm test
```

The tests check, among other things: shares of f = 11 + 7x + 9x² + 5x³ + 6x⁴ (mod 17) are 4, 10, 3, 16, 5, 2, 13; weights for holders 2, 3, 5, 6, 7 are 2, 8, 4, 8, 13; all 21 groups of five recover 11; holders 1–4 get exactly one polynomial per guess (guess 3 has a₄ = 0); 9⁻¹ ≡ 2 (mod 17); R(5) = 29, U(5) = 99; modulus 16 raises a clear error; the wrong-share results; and a 256-bit secret with p = 2^521 − 1.

## Deploy to GitHub Pages

The workflow `.github/workflows/pages.yml` runs the tests and then publishes the repository root on every push to `main`.

1. Push this repository to GitHub, with the site on the `main` branch.
2. On GitHub, go to **Settings → Pages → Build and deployment** and set **Source: GitHub Actions**.
3. Push to `main`, or run the workflow by hand from the **Actions** tab. The site appears at `https://<user>.github.io/<repo>/`.

Without Actions, you can instead choose **Source: Deploy from a branch**, then `main` and `/ (root)`. The empty `.nojekyll` file makes GitHub serve the files as they are.

## Deploy to Render

`render.yaml` describes a free **Static Site** (no server).

1. Push this repository to your GitHub account.
2. On [render.com](https://render.com): **New → Blueprint**, pick the repository, and click **Apply**.
   Or by hand: **New → Static Site**, pick the repository, then set **Build Command** `npm test` and **Publish Directory** `.`
3. Render runs the tests, publishes the site at `https://<name>.onrender.com`, and redeploys on every push.
